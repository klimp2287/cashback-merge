# Проект 2. Cashback Merge

Мини-игра в духе 2048 на поле `4x4`. На поле появляются плитки с кэшбэком,
две одинаковые объединяются в следующую:

```text
1% + 1% = 2%    2% + 2% = 4%    ...    16% + 16% = 32%
```

У игрока ограниченное число ходов, цель — собрать максимальный кэшбэк.

Но у проекта есть второй, продуктовый слой. По итоговой плитке начисляется
награда, и эта награда стоит компании денег. Поэтому максимальную награду
должна получать ограниченная доля игроков — например, не больше `20%`.
Проверяется это симуляцией на тысячах «игроков» до запуска акции.

Задание разбито на три merge request'а. Делай их по очереди.

## MR1 — Модель, конфигурация и начальное состояние

В рамках MR1 реализованы базовые сущности игры, конфигурация кампании,
создание начального состояния и вывод игрового поля.

### Игровое поле

Реализован класс `Board`, который представляет игровое поле размером `4x4`.

Поле позволяет:

* получать плитку по координатам;
* устанавливать плитку;
* проверять, пуста ли клетка;
* проверять корректность координат.

### Плитка

Реализован класс `Tile`, который хранит размер кэшбэка.

Допустимые значения являются степенями двойки:

```text
1, 2, 4, 8, 16, 32, ...
```

### Координаты

Класс `Position` хранит координаты клетки:

```text
x — столбец
y — строка
```

### Игровое состояние

Класс `GameState` хранит:

* игровое поле;
* количество использованных ходов;
* текущий счёт.

### Конфигурация

Реализованы классы `GameConfig` и `SpawnRule`.

`GameConfig` хранит:

* ограничение количества ходов;
* правила появления новых плиток.

`SpawnRule` содержит значение кэшбэка и вероятность его появления.

Пример конфигурации:

```text
1% — 85%
2% — 15%
```

### Валидация конфигурации

Класс `ConfigValidator` проверяет:

* `movesLimit > 0`;
* наличие правил появления плиток;
* корректность вероятностей;
* сумму вероятностей, равную `1`;
* корректность значения кэшбэка.

Для работы с вероятностями используется `BigDecimal`, чтобы избежать
ошибок округления `double`.

### Начальное состояние

Класс `InitialStateFactory` создаёт начальное состояние игры на основе
конфигурации и `seed`.

Одинаковые конфигурация и `seed` дают одинаковое начальное состояние.

### Вывод игрового поля

Класс `BoardPrinter` преобразует игровое поле в текстовый вид.

Пример:

```text
1 . . 2
. 4 . .
. . 8 .
. . . .
```

`.` обозначает пустую клетку.

## MR2 — Игровая механика и слияние плиток

В рамках MR2 реализована основная игровая механика: перемещение плиток,
их слияние, начисление очков и обработка результатов хода.

### Перемещение плиток

Реализовано перемещение плиток в четырёх направлениях:

* вверх (`UP`);
* вниз (`DOWN`);
* влево (`LEFT`);
* вправо (`RIGHT`).

При перемещении плитки сдвигаются в выбранном направлении, занимая свободные
клетки. Порядок плиток сохраняется.

### Слияние плиток

При столкновении двух соседних плиток с одинаковым значением они объединяются
в одну плитку со значением, увеличенным в два раза.

Примеры:

```text
1% + 1% = 2%
2% + 2% = 4%
4% + 4% = 8%
8% + 8% = 16%
16% + 16% = 32%
```

## MR3 — Награды, симуляция и отчёт

В рамках MR3 реализована система начисления наград, взвешенное появление
плиток, пакетная симуляция партий и формирование отчёта для проверки
бизнес-ограничения кампании.

### Взвешенное появление плиток

Реализованы классы `TileSpawner` и `WeightedTileSelector`.

`WeightedTileSelector` выбирает значение новой плитки на основе вероятностей,
указанных в конфигурации кампании.

Например:

```text
1% — 85%
2% — 15%
```

При большом количестве появлений плиток их распределение должно
приближаться к заданным вероятностям.

`TileSpawner` выбирает свободную клетку игрового поля и размещает в ней
новую плитку после успешного хода.

### Таблица наград

Реализован класс `RewardService`, который рассчитывает итоговую награду
на основе максимального кэшбэка, собранного игроком за партию.

Пример таблицы наград:

| Максимальный кэшбэк | Награда |
|---|---:|
| 2% | 0 |
| 4% | 50 |
| 8% | 150 |
| 16% | 500 |
| 32% | 2000 |

Награда определяется по максимальной плитке, достигнутой игроком.

### Стратегия игрока

Реализован класс `RandomPlayerStrategy`, который случайным образом
выбирает одно из четырёх направлений хода:

- `UP` — вверх;
- `DOWN` — вниз;
- `LEFT` — влево;
- `RIGHT` — вправо.

Стратегия используется для автоматического прохождения партий при симуляции.

### Симуляция партий

Реализованы классы `GameSimulator` и `SimulationService`.

`GameSimulator` выполняет одну партию: создаёт начальное состояние,
последовательно применяет ходы игрока, обрабатывает появление плиток
и рассчитывает итоговую награду.

`SimulationService` запускает заданное количество партий и собирает статистику:

- распределение максимальных плиток;
- распределение итоговых наград;
- количество игроков, получивших максимальную награду;
- долю игроков с максимальной наградой;
- средний и максимальный счёт.

Для воспроизводимости симуляции используется `seed`. При одинаковой
конфигурации, количестве игроков, стратегии и начальном `seed` результат
симуляции воспроизводится.

### Проверка бизнес-ограничения

В конфигурации кампании задаются параметры:

```json
{
  "maxRewardCashback": "32",
  "maxRewardAllowedRate": "0.20"
}
```

`maxRewardCashback` определяет порог максимальной награды, а
`maxRewardAllowedRate` — допустимую долю игроков, которые могут её получить.

Фактическая доля рассчитывается по результатам симуляции:

```text
actualMaxRewardRate =
    maxRewardGames / totalGames
```

Далее результат сравнивается с допустимым значением:

```text
actualMaxRewardRate <= maxRewardAllowedRate -> OK
actualMaxRewardRate > maxRewardAllowedRate  -> FAILED
```

Проверка является эмпирической: она оценивает выбранную конфигурацию,
стратегию, количество партий и `seed`, но не гарантирует соблюдение
ограничения для любых возможных условий.

### Формирование отчёта

Реализован класс `ReportWriter`, который сохраняет результаты симуляции
в Markdown-файл.

Отчёт содержит:

- количество сыгранных партий;
- лимит ходов;
- начальный `seed`;
- использованную стратегию;
- распределение максимальных плиток;
- распределение наград;
- количество и долю игроков с максимальной наградой;
- средний и максимальный счёт;
- результат проверки бизнес-ограничения: `OK` или `FAILED`.

### Запуск симуляции

Пример запуска проекта через Gradle:

```bash
./gradlew run --args="--config config/campaign.example.json --players 10000 --strategy random --seed 42 --output report.md"
```

Параметры запуска:

| Параметр | Описание |
|---|---|
| `--config` | Путь к JSON-конфигурации кампании |
| `--players` | Количество симулируемых партий |
| `--strategy` | Стратегия игрока |
| `--seed` | Начальное значение для генераторов случайных чисел |
| `--output` | Путь к файлу отчёта |

После завершения симуляции статистика выводится в консоль,
а подробный отчёт сохраняется в указанный файл.
